I'd restart it by restarting the agent, not by killing the engine myself. The agent stops its own engines when it gets SIGTERM (`shutdown` → `stopEngines`: it sends SIGTERM, waits up to 3 s, then SIGKILL). It starts them again when it comes back. This is steps 2 and 6 of the ledger's live-test procedure. It also keeps to the rule "kill only a PID you captured at launch", because I never send a signal to an engine.

**Before running anything**, I'd check with you:
- **Which players will restart.** All running engines restart (Follow and the DragonFly's, if both are on).
- **Nothing should be playing or paused.** The reconnect stops a paused player. On a *Device's own volume* player, LMS also sends its saved level when the engine connects. Under the repo rules that counts as touching the volume, so I check each player's mode first.

```sh
D="$HOME/Library/Application Support/LyrionPlay"

# 0. Check each LyrionPlay player's mode and volume (MACs from players/*/mac)
cat "$D"/players/*/mac
curl -s http://plex:9000/jsonrpc.js \
  -d '{"id":1,"method":"slim.request","params":["<MAC>",["status","-",1]]}'
#    → only go on if "mode" is "stop" for every player

# 1. Record the engine PIDs first (the agent deletes each engine.pid as it stops that engine)
for f in "$D"/players/*/engine.pid; do echo "$f: $(cat "$f")"; done

# 2. Stop the agent; it stops its engines
launchctl bootout gui/$(id -u)/com.crystalgipsy.lyrionplay.agent

# 3. Confirm every PID from step 1 has exited
for p in <PID1> <PID2>; do ps -p "$p" >/dev/null && echo "$p STILL RUNNING" || echo "$p exited"; done

# 4. Start the agent again; it starts one engine per player that is on
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.crystalgipsy.lyrionplay.agent.plist

# 5. Check it came back
tail -n 20 ~/Library/Logs/LyrionPlay/agent.log   # "agent started", "engine … of <name> started", "LMS: using …"
curl -s http://plex:9000/jsonrpc.js \
  -d '{"id":1,"method":"slim.request","params":["",["players",0,99]]}'   # each player connected again
```

**Things I would not do:**
- **No `pkill squeezelite`.** Matching by name is forbidden in this repo.
- **No `kill` on a PID read from `engine.pid` to restart a single engine.** I didn't start that process, and the agent would log it as "exited unexpectedly" and restart it on its crash backoff.
- **No `launchctl kickstart -k`.** I haven't checked which signal it sends. If it's SIGKILL, the engines are orphaned until the new agent's `stopOrphanedEngines` cleans them up.

If you only want one player's engine restarted, switching that player off and on again in Settings is the clean way to do it.
