## The finding

**1. If the first stamp write fails, the player loses its stamp, and "no stamp" means every server gets the empty answer** (low)
`engine/slimproto.c:581-582`, `:502`, `:702`, `:748`

- **What the comment says.** The comment on `store_name_servers` (581-582) says a failed stamp write "leaves an older stamp, which at worst offers a server the name instead of the empty answer". That only holds when an older stamp exists.
- **What happens the first time.** On a player's first naming (a new player's `-n` offer through `name_offered`, or LMS's first `setd`), the name is written by `store_name` and the stamp by `store_name_servers`. If the name write succeeds and the stamp write fails (a full disk between two tiny writes, or `name.server.tmp` can't be created), the disk has a name file and no `name.server`.
- **After a restart.** `load_player_name` sets `name_from_lms = true` because the file holds a name. `name_server_count` is 0, and `named_by_this_server` treats that as yes (502). So every server gets the empty answer, including one that has never seen the player.
- **What goes wrong.** If the first connect after that restart is to a different server (the Server setting changed, rediscovery, or a `serv` switch), that server sends its default name (SqueezeLiteMac). The engine stores it and stamps only that server. Back on the first server, which is no longer in the stamp, the engine offers "SqueezeLiteMac" there too. This is the CODE-REVIEW 2026-10-15 (3) outcome (`named SqueezeLiteMac over its name file`), reached through a failed first write.
- **How it heals.** If the first connect after the restart is to the server that named the player, there is no harm: LMS sends the name back, `store_name` returns true through `file_holds`, and the stamp gets written. So it needs three things: a failed stamp write on the first naming, then a restart, then a different server first. That's why I rate it low.
- **No test covers it.** `test_failed_write_keeps_name` (`engine/tests/test_slimproto_name.c:600`, `:618`) always starts from an existing stamp (`SERVER_A`). The "no stamp yet" case isn't pinned.
- **Possible fix.** Fix the comment, or write the stamp even when it's the only line (for example, retry it at the next connect while `name_from_lms` is true and the count is 0). Simon's call; I haven't proposed code.
